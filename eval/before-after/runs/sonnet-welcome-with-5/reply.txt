The fix is committed on a new branch, `fix-parse-size-decimals`, and the PR description is at `../pr.md`. I haven't pushed anything or opened the PR.

**Cause:** the regex in `tinyparse/size.py` matched the decimal part of the number but didn't keep it. So `"1.5k"` was read as `1 * 1024`.

**Fix:** the regex now captures the whole number, and `parse_size` multiplies it by the unit using `Decimal`. That avoids float rounding errors, and the function still returns an `int`.

**Tests:** I reproduced `parse_size("1.5k") == 1024` before the change. I added `test_decimals`, which covers `1.5k`, `0.5M` and `2.k`. The full suite (`python3 -m unittest discover -s tests`, 8 tests) passes. The skill's `check.py` also found nothing in the diff or the PR text.
